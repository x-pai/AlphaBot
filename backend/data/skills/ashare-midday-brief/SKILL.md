# A 股午盘快报

## 目标

将复杂盘口压缩为“当前判断 → 为什么 → 下午如何验证”的观察框架。读者首先知道市场的核心矛盾，再看到支撑判断的证据，最后知道哪些变化意味着判断成立或需要撤回。

这是独立的午评任务。盘后 Skill 仅作为数据工具调用参考，不继承其九段式、次日计划或交易打法。

## 数据与时间边界

- 使用本次实际开放的数据工具，调用参数与字段检查见 `references/data_sources.md`。工具不可用时允许降级，不凭文档宣称已连接。
- 行情以目标交易日 Asia/Shanghai 11:30 为截面。报告注明行情截止时刻和生成时间；实际数据早于 11:30 时标明延迟。11:30 前执行只能称盘中快照，非交易日说明休市。
- 午后补跑只用目标日上午可追溯的快照或分时序列，不拿下午最新值或全天日 K 回填。新闻核对发布日期及时间：上午消息可用于解释上午；11:30 后、生成前且不晚于 13:00 的消息单列“午间变量”，不能倒推上午原因。
- 数字必须可追溯至实际返回或已阅读的来源正文。成交额统一市场范围、币种和单位；比较基准只能是上一交易日同一时点，不能拿昨日全天或多日均值充当同期。
- 缺失数据不补造。没有可靠同期量能就不判放缩量；没有资金流证据只能推断市场风格，不能声称资金实际净流入或席位身份。核心行情与广度均无法核验时，输出数据不足说明，不强行定调。

## 分析顺序

1. **找出一个核心矛盾。** 对照指数、市场广度与重点方向，判断是普遍修复、局部强势、权重与个股背离，还是分歧扩大。选择最有证据的一种解释；不要求每天覆盖所有类型。
2. **挑选两三条关键证据。** 每条都应解释它如何支持或限制当前判断，例如指数表现与涨跌家数的背离。指标多不等于证据强，重复证明同一件事的数字合并。
3. **观察主线的质量。** 最多保留两条与核心矛盾相关的方向；有数据时点名核心股及代码，结合板块扩散、分时承接或高位反馈说明性质。热度不等于强度，个股活跃不等于板块共振，消息关联不等于因果。没有代表股数据就说明缺口，不强行点名亏钱股或凑齐连板梯队。
4. **主动寻找反证。** 哪项上午事实不支持主判断？它是否足以降低判断把握？不得只挑支持结论的上涨板块或新闻。
5. **将判断变成下午观察条件。** 选 2–3 个真正能改变当前判断的对象。写清午盘基准、何时/何种变化算确认、什么变化算失效，以及届时应怎样修正判断。

事实与解释在句子层面区分。紧凑数据表标“事实”，观点段标“判断”，观察表标“待验证”，避免每句话机械重复标签。

## 报告组织

使用 `references/report_template.md` 的骨架，默认正文约 500–800 字，证据有限则缩短。最终只交付 Markdown 正文，由自动化负责发布与通知。

### 第一屏：30 秒结论

- 标题应概括当日矛盾，不用“机会来了”等口号，不固定写成放量上涨。
- 开头 60–100 字包含：当前判断、最关键依据、下午最需要验证的一件事。读完这一段即能掌握主旨。
- 接一个紧凑行情条或小表格，放三大指数、半日成交、市场广度。其余指标仅在能改变判断时出现，来源就近注明。

### 正文：3 分钟理解

- 用 2–3 个短段解释“为什么这么看”，每段围绕一个证据链：事实 → 含义 → 限制或反证。
- 主线与情绪融入证据链，不另写重复的板块清单或整套情绪仪表盘。
- 没有分时证据不写“冲高回落”“承接增强”等路径判断；没有资金数据不把板块涨跌写成确定的资金迁徙。

### 结尾：下午验证卡

每行包含“观察对象及午盘基准 / 确认信号 / 失效信号 / 对判断的影响”，2–3 行足够。

- 对象必须具体，例如已取到数据的指数、主线核心股或同口径上涨家数，不能只写“关注量能与情绪”。
- 条件必须可观测：引用真实上午高低点、明确时间窗口内能否站稳、广度是否持续扩散等。数值基准来自数据；观察窗口属于分析设定，不能冒充历史事实。
- 不把一个瞬时跳动当作确认，不随意造出百分比、价位或精确触发线。
- 三种涨跌情景全部罗列不能替代核心判断。只写与本文判断有关的确认和反证，不追求覆盖所有可能性。
- 结束用一句话写明“出现什么，当前判断需要撤回或降级”。不固定附加低吸、追涨、控仓或仓位比例。

## 发布前自检

- 首屏能否独立说明当前判断与核心矛盾？删掉行情数字后，是否仍是能套用任意一天的空话？若是，重写。
- 每个判断能否指回事实？下午观察条件能否确认或推翻同一个判断？不能相互脱节。
- 日期、时点和市场范围一致；无下午数据、最终晋级率或当日盘后龙虎榜混入。
- 每个具体数值和个股都来自本次证据；分页不完整时不概括全市场梯队。
- 没有真实数据时明确收缩结论，不为了模板完整而凑内容。
- 报告模板中的方括号是写作提示，交付前全部填入或删去。执行 Prompt 仅使用系统支持的日期变量，见根目录 `prompt.md`，不要把报告骨架直接当执行 Prompt。
