# tdxaidata 市场数据源

`DEFAULT_MARKET_DATA_SOURCE=tdxaidata` 全量接管市场工厂的 12 个数据集和交易日历。
和股票域的 `DEFAULT_DATA_SOURCE=tdx`、`TDX_API_BASE_URL` 独立。TDX 模式禁止绑定 XGB/THS，缺失或失败不自动回退旧源。

## 本轮成本修正（2026-09-22）

- **人气榜暂停**：在任何 SDK 调用前返回 503 和原因，删除全市场 GP27 排名扫描。
- **历史股票池、历史强势/大面榜自动回补暂停**：不再由页面请求触发全市场逐股历史查询。`_history` 本身也有拦截，不能从内部路径绕过。
- **实时批量行情保留**：快照、基础信息和扩展行情每批最多 100 只。它们仍会覆盖全市场，但不属于逐股专业数据扫描。
- **候选详情硬上限 100 只**：实时池和强势候选的专业查询先检查证券数量；超过上限整次失败，不截断为看似完整的名单。100 只不是积分或原生请求次数上限，同一证券可能查询多个字段或重试。
- **取消失败展开**：专业查询失败后不再拆成逐股、逐日补查；客户端现有瞬时错误重试仍最多 3 次、共享超时预算。
- **页面明确降级**：人气榜不再自动请求；历史情绪、主线/接力分析暂停，不用空历史计算结果；大面榜只查当前交易日。独立的实时行情及板块展示保留。
- 前后端缓存版本已更新，避免复用旧扫描结果。未增加付费采集任务、自动历史回补或绕过限制的开关。

本轮仅离线验证：**46 项后端测试通过**（3 条依赖警告），前端 TypeScript 检查通过。新增验证包括禁止扫描路径不调用证券数据接口（日期识别仍可读取交易日历）、候选上限、不展开失败查询、保留原生批量调用。

下一步先向服务方确认人气 Top N / 历史池名单接口和积分计费粒度，再核对 `EverZTCount`、`DaysZTSeries`、`LastStartZT` 等字段能否替代候选历史查询。确认前不恢复全市场逐股扫描。之后再设计持久化日快照、增量更新及明确预算下的独立回补任务；这些尚未实现。

## 安装、配置与切换

```bash
cd backend
uv pip install --python .venv/bin/python -r requirements.txt
```

在受限的本地 `.env` 或部署环境配置：

```dotenv
DEFAULT_MARKET_DATA_SOURCE=tdxaidata
MARKET_DATA_BINDINGS=""
TDXAIDATA_TOKEN=your-data-service-key
TDXAIDATA_LIB_DIR=""
TDXAIDATA_TIMEOUT=30
TDXAIDATA_MAX_PENDING=8
TDXAIDATA_MAX_SYMBOLS=100
```

Key 不写入源码、示例配置、日志或报告。已有 `TdxAiData.ini` 配置也可沿用；环境 Token 优先。
SDK 固定为 1.1.1，附带 pandas。默认使用包内对应平台的原生库；外部库目录可通过 `TDXAIDATA_LIB_DIR` 指定。

SDK 在独立子进程中运行，复制原生库到受限临时目录，在临时 INI 注入 Key（权限 0600），避免修改主服务工作目录及 site-packages 配置。
原生调用超时终止子进程，下次调用重新建立连接；等待队列有上限。普通瞬时错误在同一个超时预算内最多尝试 3 次；TokenKey 错误不重试、不展开逐股回查，并暂停原生请求 60 秒。进程关闭时清理临时目录。
升级 SDK 或更换原生库后需重新运行真实验证脚本，不应混用不同版本动态库。

配置后重启后端所有 worker，并刷新已打开的前端页面。登录后访问 `/api/v1/market/source-info` 可检查实际绑定、浏览器缓存命名空间及缺失能力说明。前端首次需要时读取来源信息，成功后在当前页面内存中复用，不定时轮询；刷新页面后重新读取，旧来源缓存不会复用。服务端缓存按数据集及来源隔离。

Docker：`docker build -t alphabot-backend ./backend`。为容器提供 Token 环境变量；自定义库目录需匹配目标平台并保持只读挂载。子进程使用临时副本。

## 数据与计算口径

| 数据集 | 数据来源 / 定义 |
|---|---|
| quotes | 批量行情，涨幅 = 现价 / 昨收 - 1 |
| pools | 实时行情和涨跌停价判定状态；GP15 补历史连续涨停；逐只涨跌停事件补时间；概念为 `get_relation` 分类 |
| universe | 行业与概念列表、板块快照、主力净流入、涨跌家数；平盘数为成分总数减上涨及下跌数（包括停牌） |
| members | 同一通达信板块代码对应成分、行情、换手率及资金 |
| plate_index | 通达信板块日 K，保留板块代码和交易日期 |
| fundflow | `get_exday_data.Amo` 四档买入/卖出金额；主力 = 超大单 + 大单；金额元转万元；不混用主买/主卖列 |
| turnover | 沪深指数分钟成交金额累计；不包含北交所；预测按昨日同分钟成交占比估算 |
| payoff_strong | 最近 20 个交易日至少 2 次封涨停，排除 ST，展示 N 天 M 板；不等同原编辑名单 |
| payoff_hot | 暂停，返回不可用原因；不执行全市场 GP27 排名扫描 |
| payoff_drawdown | 当日曾涨停且未封板、非 ST 股票，分钟收盘价相对此前分钟最高价的最大回撤；不是逐笔最大回撤 |
| surge | 行情涨速 ≥3% 的前 50 只；标明规则筛选 |
| trending | 正涨幅板块按涨停家数、涨幅排序前 10；标明规则计算，不伪造新闻催化 |

连板只累计连续交易日的封涨停，炸板和缺失交易日中断连板。跌停池不包括“曾跌停”。
当前封单不使用历史最大封单替代。未知首次开板时刻保持 null，不使用最后开板时刻冒充。
缺失数值保留 null；缺失关键资金/广度的板块不参与评分。板块成分表保留未知项并显示 `--`，成分统计只使用完整样本。

原分时情绪、短线情绪指数使用专有 TQLEX 指标，尚未发现 SDK 的等价接口。TDX 模式停止这些旧请求，返回明确 `unavailableReason` 并在市场页面展示说明；不计算同名伪指标。
涨停原因/催化新闻不等同概念归属，当前只显示分类及规则说明。
历史证券集合使用当前 A 股列表，不覆盖已退市证券的完整历史截面。

## SDK 1.1.1 兼容与性能

- 实时候选专业数据使用有界日期范围。GP15 是稀疏事件序列：无事件证券可以返回 null，不能推断为接口失败；连板统计按完整交易日历对齐。历史全市场窗口扫描已停用。
- 部分仅含稀疏 GP 字段的请求曾打印错误；查询增加每日人气 GP27 作为响应检查字段，返回后仅保留业务需要的字段。日期范围请求本身已验证可用，不能把无事件返回 null 一概当作失败。全市场兼容逻辑仍待真实历史验收。
- 多证券涨跌停请求实测代码拼接错误：逐只查询并检查返回 Code。
- 日线当日可能尚未更新：实时榜单涨幅使用快照，不能把当日日线占位值当成实时价格。
- `J_start=0` 为待上市证券，专业扫描按已上市证券过滤。
- SDK 原生错误往往打印后返回空值；适配器捕获错误并转为 503，避免缓存成正常空列表。
- 专业数据列表在 SDK 内部逐股请求，和原生批量行情不同。停用前实测人气榜首次约 119 秒、实时池约 15 秒，仅作旧版本性能记录；当前已禁止全市场专业扫描，候选详情仍有调用成本。尚未核实按请求、证券、字段或数据量计费，不能把批量调用视为一定节省积分。

## 验证

```bash
cd backend
.venv/bin/python scripts/probe_tdxaidata.py --full
.venv/bin/python scripts/verify_tdxaidata_market.py --full
.venv/bin/python -m pytest app/tests/test_tdxaidata_market_source.py app/tests/test_market_routes.py app/tests/test_market_cache.py -q
cd ../frontend
./node_modules/.bin/tsc --noEmit
```

脚本只读市场数据，不输出 Key。实时验收覆盖当前允许的数据集并校验响应模型，明确跳过已暂停的人气榜。`--history` 直接退出，不发起 SDK 请求；不能用于绕过成本限制。Key 恢复及成本规则确认前，不运行真实验收命令。
可用 `--payoff` 重测强势/大面，`--diagnose`（探测脚本）核对 SDK 日期及字段。

回滚：恢复 `DEFAULT_MARKET_DATA_SOURCE=xgb`，清空或恢复原显式绑定，重启后端。无需删除其他来源缓存。
